================================================================
1. PROJECT OVERVIEW
================================================================

ScottsTechX is a Ugandan e-commerce marketplace that runs on:

  - Android app (Kotlin + Jetpack Compose, min SDK 30, target SDK 35)
  - Fastify backend (Node.js + TypeScript) on port 3001
  - Embedded PostgreSQL on port 5433 (embedded-postgres package)
  - Firebase Authentication (real email-link verification)
  - OpenRouter LLM (meta-llama/llama-3.3-70b-instruct) for AI
  - Coil 2.x for image loading
  - Naver/Navigation-Compose for routing

The app has two roles: BUYER and SELLER. Each role gets its own
bottom navigation bar, its own AI assistant screen, its own dashboard,
its own settings panel, and its own messaging inbox.

The founder's biography is seeded into the CMS table:
  "Kato Fred, Ugandan cybersecurity analyst, web dev and software dev."

2. HOW THE TWO HALVES TALK
================================================================

Android app --> http://127.0.0.1:3001/api/v1/...
Backend     --> PostgreSQL on 127.0.0.1:5433

The single API entry point is defined in
scottsx-android/app/src/main/java/com/scottsx/app/data/remote/V2Client.kt.
Every network call goes through one of the suspend functions in that
file. They share one OkHttpClient and a single bearer-token from
SessionCache.

Auth flow:
  1. User signs up via Firebase Auth.
  2. FirebaseAuth.signInWithEmailAndPassword returns an idToken.
  3. App POSTs that idToken to /api/v1/auth/firebase/sign-in.
  4. Backend verifies the token, mints its own JWT (24h),
     and stores the user row in Postgres.
  5. All subsequent requests send `Authorization: Bearer <jwt>`.

6. ANDROID ARCHITECTURE
================================================================

6.1. Single source of network truth
----------------------------------------------------------------
V2Client.kt owns every endpoint. It exposes typed suspend functions:

    suspend fun fetchProductsList(): List<Product>
    suspend fun ask(prompt: String, screen: String): AiReply?
    suspend fun fetchStoreSettings(): StoreSettings
    suspend fun updateStoreSettings(s: StoreSettings)
    suspend fun fetchUserSettings(): Settings
    suspend fun saveSettings(s: Settings)
    suspend fun updateUserProfile(...)
    suspend fun updateSellerProfile(...)
    suspend fun fetchSellerProfile(): SellerProfile
    suspend fun fetchConversations(): List<Conversation>
    suspend fun fetchMessages(conversationId: String): List<V2Client.Message>
    suspend fun sendMessage(conversationId: String, text: String)
    suspend fun markRead(conversationId: String)
    suspend fun nearbySellers(lat: Double, lng: Double): List<NearbySeller>

All return either the typed model, a sealed class result, or null.
No raw JSON escapes past this file.

6.2. Two AI assistants
----------------------------------------------------------------

BUYER AI — RealAiChatScreen.kt
  - Top bar with title and gradient
  - Quick-reply chips (HorizontalPager): "What's near me?",
    "Cheapest Samsung A55", "Summarize my transactions", etc.
  - LazyColumn chat log
  - Composer with send button + back nav
  - BEFORE calling V2Client.ask, it fetches the full catalog
    (first 40 products) and prepends a textual summary:

      "Live marketplace catalog (24 products):
       - iPhone 15 Pro 256GB Natural Titanium (Electronics)
         UGX 4500000 from Tech Hub Uganda [id=...]
       ..."

    so the LLM can answer store-specific questions accurately.

SELLER AI — SellerAIAssistantScreen.kt (NEW)
  - Gradient header (blue -> purple -> pink)
  - 4 quick tools in a 2x2 grid:
      Sales analytics    (weekly revenue, orders, top sellers)
      Low stock          (refill alerts, demand signals)
      Pricing tips       (competitor comparison, margin lift)
      Marketing ideas    (campaigns, promos, retention)
  - Chat area below the tools
  - Each tool adds a user + ai message to the chat
  - The user can also type freeform questions; same backend

6.5. AddProductScreen.kt — AI suggest from photo
----------------------------------------------------------------
  - Step 0 (Basics): name + description + category
  - Below the description: "✨ AI suggest from photo" button
  - When seller has added at least one image URL, the button is enabled
  - Tapping it runs a heuristic generator:
      Looks at the URL for keywords ("phone", "iphone", "samsung",
      "shoe", "nike", "dress", "ankara", "kitenge", "rice",
      "headphone", "lipstick", "makeup", "watch")
      Maps to:
        Title       ("Premium Smartphone — Like New")
        Description (full sentence with delivery/trust info)
        Category    (Electronics / Sports / Fashion / Beauty / Groceries)
  - Preview shows the suggestion with "Apply" or "Dismiss"
  - Real backend wiring exists at /api/v1/ai/v2/generate-product
    (currently heuristic only — easy swap)

6.6. SignUpScreen.kt — Firebase real email-link verification
----------------------------------------------------------------
  Flow:
    1. User enters email
    2. Tap "Send verification email"
    3. App calls FirebaseAuth.getInstance().currentUser
        ?.sendEmailVerification()
       Firebase sends an actual email to that address
    4. App shows "Verification email sent" + "I've verified — continue"
    5. User taps the link in their email
    6. They come back to the app, tap "I've verified — continue"
    7. App calls user.reload() and checks isEmailVerified
    8. If true, signup proceeds; if false, retry message

  The backend has a parallel endpoint
  POST /api/v1/auth/firebase/send-verification-email that uses
  Firebase Admin SDK's generateEmailVerificationLink.

6.7. SellerBottomBar.kt — balanced spacing (v0.22.1 fix)
----------------------------------------------------------------
  Layout: weighted Row split into left half + center spacer +
  right half:
      [Home | AI]    [Add FAB]    [Messages | Analytics]

  - Left half is a Row with SpaceEvenly for Home and AI
  - Right half is a Row with SpaceEvenly for Messages and Analytics
  - Center Spacer reserves 72dp for the FAB (which is
    64dp + 14dp offset above the bar)
  - Each side has equal weight(1f) so the FAB is visually centered
    and the AI button is no longer crowded next to it

9. CONVENTIONS
================================================================

Code style
  - Kotlin: tabs for indentation, no wildcard imports, 4-space continuation
  - Compose: remember + collectAsState for state, rememberCoroutineScope
    for launch effects, no business logic in composables

Naming
  - Composables: PascalCase, screens end in "Screen"
  - Functions: camelCase
  - Routes: kebab-case strings ("seller/store-settings/policies")
  - Files: match the primary type they contain

State management
  - SessionCache (single source of truth for the current user)
  - UserPrefs for non-secret persisted prefs (theme, language)
  - Each screen has its own remember{} mutableStateOf for ephemeral UI

Backend
  - Zod for input validation (z.object({...}).parse(request.body))
  - Errors thrown with custom classes (UnauthorizedError, etc)
  - JWT signed with HS256, 24h expiry
  - All routes under /api/v1/

Testing
  - Manual end-to-end on the physical device (Tecno 042532598N000481)
  - Backend smoke-test via curl /healthz and /api/v1/products
  - uiautomator dump used for screen text introspection

10. KNOWN GOTCHAS
================================================================

- Unsplash images load only if:
    (a) The imageUrl is a real URL, NOT a placeholder like "phone"
    (b) The ProductImage composable uses Coil.imageLoader(ctx)
        (NOT ImageLoader.Builder(ctx).build())
    (c) The phone has internet (test with adb shell ping 8.8.8.8)

- The buyer home shows live API data; when the API is empty
  it falls back to MarketplaceDataSource.products.

- Signup email verification uses the Firebase email LINK model,
  not a 6-digit code. The "I've verified — continue" button
  re-fetches isEmailVerified.

- The 6-city location selector shows real Ugandan cities from
  the seed script. Tapping a chip selects the city and triggers
  a /api/v1/sellers/nearby call.

- Embedded-postgres binary on Windows: `npm install` may need
  `--force` to copy the right .node binary. See windows-npm-install-corruption
  skill.

- Gradle builds use -Dkotlin.compiler.execution.strategy=in-process
  to stay under the 4 GB Gradle JVM cap.
